Audio Sinks & Device Drivers

Depending on deployment topology, the audio sink renders speech directly to server hardware speakers or streams bytes over HTTP to the client browser:

WebAudioOutput (Browser Audio Context) Active

Serves encoded audio over REST static endpoint /api/pipeline/audio/{filename}. The browser decodes PCM WAV via HTML5 <audio> element, bypassing server hardware drivers.

SystemSpeakerOutput (Windows Hardware) Server-Side

Utilizes Windows Multimedia API (winsound.PlaySound or sounddevice) to route PCM audio directly to the host machine's DAC and line-out speaker jack.

SilentAudioOutput (CI/CD Headless) Testing

No-op output sink implementing IAudioOutputService for automated unit testing in headless CI/CD environments with zero speaker devices.

class IAudioOutputService(ABC):
    @abstractmethod
    def play(self, tts_result: TTSResult) -> PlaybackResult:
        """Transduces synthesized speech to physical sound."""

class PlaybackResult(BaseModel):
    played: bool
    output_sink: str = "web"
    latency_ms: float = 0.0
    error: Optional[str] = None
